# M18.1.2 — persistent reported session budget and interrupted-task recovery

Version 0.0.35. Implementation complete; automated regression CI pending. M18.1's real-account task gate remains open (7/8, 87.5%); expanded project approximately 83%.

The previous budget spent serialized input bytes plus reserved output per request, so actual usage could be far below exhaustion. Configuration also capped maxTokens at 500,000 and failed tasks never entered history. The session now counts provider-reported total_tokens across all tasks and connection tests, including incomplete responses. maxTokens accepts up to 1,000,000,000. Updating only selected limits preserves the others. Usage and all limits persist atomically in .axiom/projects/.assistant-session.json (or the selected project store root); disconnect/reconnect, refresh and daemon restart do not reset them. No key, conversation, objective or reasoning is stored in this ledger. It applies to the local installation/store, not the whole OpenAI account. Older releases' usage cannot be reconstructed. Unreported/failed transport usage is flagged separately; no invented byte estimates are shown as real usage. Save the .axiom directory when updating the engine.

The next request is blocked if reported session usage has reached the configured cap. Output is capped by the remaining balance, but input cost is only known after the response, so one request can overshoot the balance. Its usage is still counted, queued tools are held, and continuation requires raising the cap. A final response with no pending tool calls can finish normally. Request count, tool count, context size and time remain independent bounds, with distinct errors. This is not a guaranteed money/spend cap; provider billing remains authoritative.

Budget/time-interrupted tasks retain the original objective, exact in-memory model/tool transcript and unexecuted tool calls. A subsequent chat submission with Continue pending proposal checked passes resumeTaskId, reusing the proposal and executing only pending calls before continuing. Completed commands are not repeated. Exhausted-budget attempts are rejected before replacing the pending task. Revision checks reject resuming a manually changed proposal/MAIN; use a fresh task instead. Failed objectives and truthful interruption status are also retained in bounded conversational history. Checkpoints survive disconnect/page reload within the running daemon, not daemon restart; only the usage ledger and limits survive restart. No automatic resume, retry of ambiguous requests or human acceptance is introduced.

Config shows persistent used/limit/remaining totals and unknown-usage requests. The chat header places a blue 0–100% meter before the isolation notice; it updates from daemon status and immediately after a limit change, caps visually at 100% and exposes exact totals in its title/accessibility attributes. The demo remains OpenAI Assistant Workshop; no duplicate project is required.

Backend acceptance covers 11,000 used / 10,000 limit -> raise to 20,000 -> 9,000 remaining; daemon recreation without credentials; one-million limit; large bytes with low reported tokens; pending mutation replay once; completed mutation retention; and stale-proposal/invalid-limit refusal. Browser acceptance adds exhaustion/update/resume and reload meter checks to existing configuration/chat/proposal checks. Actual account response quality remains a user-only gate.
