# Architecture and product integration audit — Engine0.0.56

Date:2026-10-22. Scope: current Engine review branch based on Platform P5, jointly with Platform0.1.7. The audit combines source/contract inspection, dependency checks, runtime tests and real browser workflows. It is not a claim that every possible scene, device, account, platform or Unity signature has been exhaustively certified. Final exact revision/check/browser results belong in the delivery evidence; historical reports do not certify this branch.

## Architecture map and responsibility

| Layer | Confirmed implementation and role | Boundary/remaining limitation |
| --- | --- | --- |
| Platform host/Hub | Owns persistent project/install catalogs, credentials, public release discovery, generic AI/GitHub transport, session processes and diagnostics | Cannot import Engine scene/PMD/physics types; self-update download is manual |
| Engine adapter | Validates manifest/IPC/product/project identity, authorized roots/formats, folder lease, create/open/save/close/rename/import and product daemon startup | Official prepared installation is executable software, not an untrusted project payload |
| Product daemon | Authenticated loopback HTTP, commands, authoring revisions, project/assets/scripts, bridge, proposals, PMD, reviewed Apply and native dialog ports | Bootstrap domain services and Rust native daemon are not interchangeable in every endpoint |
| Command bus/protocol | Structured envelopes/correlation/actors, ordered disk operations, revisions, event deltas, tool schemas/catalog, trace/error history | Semantic tool availability does not imply complete Unity API coverage |
| Rust core/Wasm | DOM-free stable identities/handles, authoring/runtime primitives, animation, 2D and CPU physics; renderer and replay/diagnostics crates | Native/Wasm parity is tested for declared contracts; physical GPU backend acceptance is separate |
| Browser editor | Scene/Game, hierarchy, components/Inspector references, assets/scripts, docking/detached panels, undo, compilation/play, runtime bridge and chat/review presentation | Browser presentation is not the credential authority or arbitrary filesystem/process API |
| C# scripting | SDK8, generated bindings/contracts, compilation/job state, browser runtime bridge, reflected fields/references and gameplay callbacks | SDK surface remains partial; M19 has not frozen the complete member denominator |
| Simulation/render/media | CPU/Wasm2D/3D physics, WebGPU/Null renderer, materials/cameras/lights, 2D authoring, audio, animation, scene/resources/prefabs and testing/profiler services | Dense editor physics performance remains a known concern; GPU physics/production shader expansion is future work |
| Agent workflow | Discovery/semantic tools, bounded requests/budgets, plans/checkpoints, domain verification, isolated proposals, conflict hashes, human Apply and recovery | Controlled responses verify mechanics, not live-model intelligence, pricing or reliability |

Inspected implementation anchors: `platform/adapter.mjs`, `daemon/bootstrap/server.mjs`, `command-bus.mjs`, `scene-workspace.mjs`, `workspaces/`, `agent/openai-assistant.mjs`, `github/publication.mjs`, `apps/editor/src/`, `engine/core/`, `engine/renderer/`, `engine/scripting/`, `engine/wasm/`, `protocol/schema/` and generated semantic tools/bindings. Platform equivalents are documented in its release contract. Domain-specific engine modules remain in Engine; extracting the whole daemon/agent layer would violate the adopted ownership split.

## Findings corrected in this revision

1. **AI connection split-brain.** The shared provider knew the Hub credential, but Engine retained `connected=false` and required its own generation probe. Engine now derives hosted readiness from verified Hub state and is ready on reopen without a second login. Status exposes connection scope and effective/override selections.
2. **Product account authority.** Product account buttons and raw HTTP routes could connect/disconnect a session account. Credential inputs/disconnect controls are removed from product UI, product routes refuse account mutation and the Platform broker independently denies product credential replacement/account control. Project repository/publication settings remain.
3. **Missing model inheritance.** Empty model and Same as Hub reasoning now resolve against live Hub defaults, with independent project overrides preserved. A different model uses inherited effort only when supported; otherwise provider default is explicit in effective status. Model testing is separate; generation tasks capture their effective selection.
4. **Version drift.** Engine package/descriptor/state report0.0.56. Hub version is rendered from the host catalog rather than stale HTML. Project lists show actual installed/running product versions; users do not edit game projects to register a product revision.
5. **Bundled version overriding chosen installation.** Bootstrapping an older bundled folder could change the persisted selected installation. Startup now registers the folder while preserving an existing choice; the regression test restarts with the older bootstrap manifest.
6. **No prepared release catalog.** Platform adds official public GitHub stable-release manifests, bounded downloads/hash verification, safe staged extraction, compatible artifact selection, update badge/self-update banner, side-by-side versions, handshake-before-activation and existing deferred activation/rollback.
7. **Storage and diagnosis.** Separate persistent product storage is exposed below project settings. Changes affect future destinations. Sanitized diagnostic export omits credentials, private paths, project contents and authenticated URLs. Related settings are validated before preferences are persisted, preventing partial preference changes on a rejected request.
8. **Default storage versus existing projects.** Registered projects retain their original grants across a storage-default change, while unknown outside paths remain denied. Deletion revalidates protection for project/product storage, installations and registered neighbors at execution time. The filesystem is not moved by a default change.
9. **Credential defense in depth.** Standard OpenAI/GitHub/Hub secret environment variables are stripped before product fork; the common GitHub transport validates its fixed API origin before attaching credentials. Product publication also excludes the Math Lab source repository alongside the other Axiom sources. This hardening does not assert that an earlier parent-broker URL check was absent.
10. **Graphics initialization was too eager to abandon rendering.** A controlled capability probe showed an unusable preferred device but an available explicit fallback adapter. The renderer now tries that adapter, treats timestamps as optional and reports software fallback distinctly. Null remains available when neither device works. Shared browser test options avoid forcing Linux Vulkan flags on Windows; pixel/capture assertions are retained. This does not implement GPU physics or certify physical GPU performance.
11. **Obsolete integration tests.** Hosted regression tests previously connected accounts from product endpoints, certifying the wrong authority model. They now connect through the Hub or inject a controlled shared provider for domain-only fixtures, retaining publication/MAIN/isolation/cancellation assertions.

## Validation and interpretation

- Engine final full check:450 tests passed, including build, generated tools/bindings, schema, architecture and declared daemon parity checks. Separate Rust formatting/clippy/workspace checks passed with44 native tests.
- Platform check:52 passed, zero failed and one optional native recycle test skipped (53 total). Covers real Engine/Math lifecycle, shared account authority/inheritance, request cancellation, failed provider, persistence, publication conflicts and installation/release failure guards.
- Joint real-browser P3, P4, MVP and product-release flows pass with no page errors. The product flow checks a real Engine0.0.56 plus controlled future release metadata, deferred activation, rollback, storage persistence and diagnostic export. Future version numbers in fixtures are not published product versions.
- Full Engine browser milestone matrix is recorded separately per case in delivery evidence. A restricted attempt could not compile .NET; an authorized M7 rerun completed actual C#/Wasm physics. Its old WebGPU label was not an assertion of the backend; the test now records the actual renderer separately. Independent M2 pixel assertions and M18.3.8 PNG/capture/runtime acceptance passed using the explicitly reported software WebGPU fallback. Do not classify that restricted compilation failure as a proven engine regression, or use one passing rerun to erase unrelated intermittent failures.
- Both exact prepared Engine0.0.56 and Math Lab0.1.2 ZIPs passed hash verification, safe extraction, real process handshake, create/save/close/reopen and persistent installation catalog restart in an isolated profile. The release transport was controlled local bytes, not a claim of published remote assets.
- A real native component drag remained assignable and cleared highlights despite source/target DOM replacement during a concurrent scene snapshot; DOM identity alone did not reproduce issue55. The regression keeps assignment and cleanup assertions.
- Real OpenAI/GitHub accounts were not used. GPU-browser output can be software-backed; no physical GPU-physics claim, live-account quality/cost claim or cross-OS prepared-package claim follows from these tests.

## Existing issues and limits retained

GitHub #47 (Inspector detach under slow persistence), #51 (M17 runtime motion) and #55 (reference highlight after drag) were confirmed open during this audit. Their earlier causal hypotheses remain hypotheses. Current browser outcomes are recorded without claiming a permanent fix absent controlled reproduction/regression. Do not remove assertions, force-click, retry away failures or raise timeouts to close them.

Standalone game build/export is still missing. Dense end-to-end physics performance needs dedicated reproducible workloads before acceleration design; isolated CPU speed and Null FPS do not prove physical GPU throughput. Full Unity editor/platform/package compatibility, production shaders/compute/GPU solvers, device coverage and clean-machine/manual native/account acceptance remain outside current completion claims. Rust daemon parity checks cover declared vectors rather than every JavaScript domain service.

## Development recommendation

Finish review/integration of the stacked product adaptation and this correction before treating Engine main as the new baseline. Preserve all recovery refs and native documents. Publish only version-matched prepared artifacts through the shared release contract. Then start M19.1 reproducible Unity6.3 inventory, M19.2 member mapping/priorities and M19.3 conformance/performance contracts. M20–M39 implement functional compatibility; M40 hardens. No M19–M40 acceptance or whole-API percentage is awarded by this audit.
