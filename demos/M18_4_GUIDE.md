# M18.4 — two independent GitHub demos

Run npm run demo:m18-4 in a prepared Engine checkout, then start directly with npm run dev or add the generated projects to Platform. The demos separately exercise creating a new repository and linking an existing repository. TestRepo is reserved for authorized tests, never prelinked to these demos. Use disposable repositories; credentials must be entered in the app, never chat.

In the current Platform Hub, connect via Settings → GitHub Account (top GitHub icon). Direct Engine uses its GitHub panel. A connected account lasts for the host/daemon session; token is memory-only. Each project keeps its own destination/branch/preferences/history. Sharing an account does not grant publish permission. Use the token type/scopes described by current GitHub settings/documentation; private/new repositories need suitable access, not public-read-only scope.

For create mode, open the first demo, choose Create a new repository in its editor GitHub destination, enter the intended disposable name/privacy and create. Progress/error reason must be visible. Success switches to Use existing repository with the new destination selected. For existing mode, manually create a disposable game repository, open the other demo and choose it/branch from the destination controls. Destination changes autosave; refresh lists with the icon. Keep both project settings isolated.

Make and save a scene edit. Opening GitHub automatically reviews saved changes when configured. Inspect the changed-files window; the main panel summarizes count/destination. One action performs initial review or publish after a valid review. Publish only an intended saved MAIN revision to the chosen branch. Verify commit/files from GitHub and reopen/download through product import. Uncertain results require reconcile/history rather than blind retry; divergent remote head must reject without overwrite.

Disconnect restores the token form and affects shared hosted editors; closing one editor leaves others connected. Restart clears the account but preserves each project's destination/preferences/history. Publication defaults are ON only for new settings; explicit older values are retained. Controlled fixture acceptance and connector-delegated TestRepo tests do not prove native HTTP/GraphQL with a real token. Manual native-account validation was explicitly deferred under ADR0034; it remains separate from the nine accepted implementation groups.
