# M10 — 2D production foundation

Version 0.0.22. Implementation awaiting full CI acceptance; no closure claim yet.
Read ADR-0023 and M10_CURRENT_REPORT.md for contracts and evidence.

Enable 2D in Ajustes → 2D Scene / Camera on an empty/sprite project. Mesh/HDR
mixing rejects the change atomically. Existing scenes are unaffected. The Game
camera becomes orthographic; pixel-perfect mode faces the XY plane from +Z,
snaps camera translation to pixels, uses nearest atlas sampling and a reference
height at an integer scale. Unused rows/columns are letterboxed; smaller canvases
crop the reference extent at 1x. Scene uses its independent editor camera without
snapping. Arbitrary rotations/noninteger sprite texel sizes can still distort pixel
art; author world Size × pixelsPerUnit / atlas-frame pixels as an integer. Demo
sprites use integer texel sizes. ReferenceHeight / pixelsPerUnit controls Game's visible vertical units.

Optional components in searchable Add Component:

- Sprite2D: requires sprite Renderable; atlas columns/rows/frame, world size,
  tint, stable order, lit/unlit and flip axes. PNG dimensions must divide the atlas.
- SpriteAnimation: requires Sprite2D; ordered frame indices, fps, loop, autoplay.
  First authored frame previews while stopped; runtime advances only in Play.
- Tilemap: imported PNG atlas, width/height, tile size and row-major cells. -1 is
  empty; row 0 is the top. Inspector brush and cell grid issue one Undoable change.
  Resizing preserves overlapping rows/columns; new cells are empty. Painting is
  visual: authored Collider entities must be adjusted independently.
- Light2D: world position, radial color/intensity/radius over scene ambient.
  Live Scene gizmos preview light position. No 2D shadows/normal maps claimed.
- Particles2D: seed, capacity, rate, lifetime, initial speed/spread, gravity,
  size/color/order. Local upward fountain follows the emitter transform; capacity
  replaces older emissions. Rust analytic samples are reproducible at equal time.
  Stop resets all emissions. Particles do not collide with physics.
- UI2D: normalized screen rectangle, panel/button, color/order, none/togglePause.
  Drawn only in Game, independent of world camera/hierarchy transform. Buttons
  activate during Game Play, consume pointer input and pause transient simulation.
  Stopped preview is inert. Panels are visual, not input blockers. Text, layout,
  arbitrary callbacks and a full widget toolkit remain outside this foundation.

All setters are public scene.<componentKey>.set plus scene.twoD.update, with
revision checks, Undo/Redo, Save and isolated AI proposals. Query entity components
through entity.query; scene.query includes global twoD settings. API describe/search
uses the same canonical schema. No direct agent source mutation is permitted.

World sprite transforms continue through Rust/Wasm and existing angular 2D physics.
Sprites and colliders have independent sizes; updating visual size does not resize
Collider. C# movement and Scene/Game/UI input routing use the existing ScriptRuntime.

Renderer batches consecutive identical PNG/white textures after stable order,
then draws screen UI last. Alpha is premultiplied, blending occurs in linear color, and an sRGB canvas view
encodes output for display; PNG unlit colors stay faithful. Depth writes are disabled.
A single shared atlas minimizes actual draws; rearranging textures may increase
batches. No GPU atlas packer or occlusion/alpha picking is claimed.

Bounds: 8192 quads, 1024 component batch groups, 4096 total tile cells, 2048 total
particle slots (32 emitters, 512 each), 16 lights, 128 UI controls; existing 1024
entities, 128 assets and 192 KiB persisted document limit still apply. Upload
buffer capacity is 2,555,904 bytes plus 528 light-uniform bytes, one GPU pipeline,
two samplers and at most 129 texture bind pairs. All resources retire on disposal;
snapshot changes clear bindings, load revisions and prune old textures.

Diagnostics rendering.mode=2d reports quads/visible/culled/batches/tiles/particles,
lights, bounded animation states, elapsed time/pause, viewport/integer pixel scale,
used/capacity vertex bytes and backend. WebGPU submitted counts actual draw calls;
Null uses the same plan, submitted=0 and pixels=unavailable. CPU benchmark reports
planning cost only, excluding GPU/full-frame/physical hardware claims.
